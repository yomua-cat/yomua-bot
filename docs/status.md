## 当前实现

- 入站消息保存作者类型、平台用户身份、观察角色、提及、引用、绑定版本和来源 metadata；适配器只负责接受，插件事件由事务提交后的 `MessageAccepted` 唯一发布，并在插件协议中归一为一条 `message.received` 通知。
- 消息接收入库使用结构化 `AcceptedMessageInput`，在同一事务中分配会话序号、写入消息并创建 Outbox 事件。
- 回复任务会冻结连续输入；原消息逐条保存，生成期间的新消息进入下一轮。
- 上下文中只有角色真实发送且归属当前观察角色的消息才使用 `assistant`；当前批次只作为当前输入出现一次。
- ctl 客户端、服务端和帮助文本使用统一 canonical 命令定义，支持一段、二段和三段命令；Unix socket 使用版本化结构化 `ControlEnvelope`，bot 不再解析人类 `cmd` 字符串。
- QQ 管理指令会先保存为 `author_kind=system_command` 的消息并创建 `MessageAccepted` Outbox 事件；Outbox 消费时由 `CommandHandler` 做权限和绑定校验，控制回复复用 `reply_tasks` 的生成、发送、未知和历史落库状态机，不再由适配器直接发送。
- 记忆候选与正式可见记忆分离；上下文只在来源会话读取会话记忆，跨会话仅读取当前全域用户且明确标记共享的记忆。跨会话记忆只作为角色的内部上下文使用，不向用户透露来源会话；没有用户身份上下文的接口只返回本会话内容。
- `memory update` 先把 pending 请求写入记忆元数据，再通过 decision LLM 生成受限修改建议；程序校验并做乐观并发检查后才写入，记忆原文不在普通控制响应中返回，模型不可执行删除动作。
- 跨会话记忆默认允许角色内部使用，但不把来源会话、原始群聊或记忆标识暴露给用户。用户可通过 `memory sharing request <character-id> <user-id>` 登记高优先级禁用请求；管理员使用 `memory sharing confirm ... --confirm` 后，未来跨会话检索会被数据库层阻止，来源会话仍可读取；`memory sharing cancel ... --confirm` 可恢复共享。
- 未配置对话模型时保留消息，不发送伪造回复。
- 黑名单在解析会话和参与者之前执行；查询失败按拒绝处理，不为被拦截目标创建新身份记录。
- 图片、文件等非文本段保存类型和平台字段，并以“没有媒体识别能力”的占位摘要进入上下文，不伪装成已完成识别。
- 关系交互按来源消息幂等记录，Outbox 重试不会重复增加熟悉度。
- 全域用户身份已落地：`users` 以 `(platform, external_id)` 唯一，用户参与者通过 `participants.user_id` 关联；关系数据库主键和领域对象均使用 `(character_id, user_id)`，会话 `participant_id` 只作为解析入口。同一平台用户跨群/私聊共享关系。旧关系迁移会按既定规则合并并有 SQLite 回归测试覆盖。
- 用户参与者写入时由仓储和 SQLite 触发器共同补齐全域身份；删除后的历史占位改为 `system` 角色，因此正常 `user` 参与者不会留下空 `user_id`。
- 用户合并会按显式来源和目标身份读取平台账号，不依赖数据库 ID 排序；状态控制中会话状态与心情写入使用同一 SQLite 事务，任一部分失败都会整体回滚。
- 关系交互幂等表也已从 `participant_id` 迁移为 `user_id`；旧数据按参与者映射到全域用户，重复的同一来源消息只保留一条，避免跨会话重复累计熟悉度。
- OneBot 当前把平台命名空间写为 `onebot_qq`，外部 QQ 号只作为该命名空间内的 ID；相同外部 ID 在不同平台会生成不同全域用户。关系服务的入口仍以会话 `participant_id` 定位，再由仓储映射到 `user_id`，这是内部适配边界，不是第二套用户身份。
- 记忆表增加可空 `user_id`；候选记忆会从来源 participant 回填用户归属，上下文按角色、当前会话和全域用户范围检索。没有可靠来源的旧记忆保持无用户归属，不会被错误绑定。
- 默认配置目录统一为启动目录下的 `config/`；首次启动逐份生成带占位说明的模板。根目录已有的本地配置不删除，继续使用时需显式传入 `--config-dir .`。
- 主动发言的每日额度已写入 `behavior_states`，进程重启不会清空当日计数；默认冷却为 10 分钟、每日最多 10 次。
- 主动额度预留在 SQLite 事务中原子完成；并发后台 tick 只能有一个任务通过同一会话的冷却和每日上限检查，避免重复主动发言。
- 候选记忆保留来源和理由；只有来源完整、类型为直接陈述、重要度至少 0.5 且候选置信度至少 0.8 的项目才会被程序自动确认，推断和低置信度候选继续留在候选区。
- 插件只能读取当前会话可见的正式记忆；插件发送消息、修改角色状态、写入记忆和写入关系已在统一 RPC 分发层拒绝。角色、绑定和关系读取也必须带明确范围，关系读取使用全域 `user_id`，不能把 `participant_id` 当作稳定身份。
- OneBot 发送回执只有同时满足 `status=ok` 与 `retcode=0` 才视为成功，失败回执不会误标为已发送；未知结果核查到平台明确失败时会自动重新排队，网络核查失败仍保持人工核查状态。人工 `reply unknown retry` 也必须先查询平台，不能用确认参数绕过核查。
- 平台自身回声只会写入已有会话的对账记录，不会因为回声创建新的用户或参与者；引用目标晚到时会在目标消息入库后回填本地引用关系，历史查询对同序消息使用消息 ID 做稳定排序。
- 会话删除会先把对应的待处理/处理中 Outbox 事件标记为死信；处理器入口再次确认源消息仍存在，避免删除后的事件继续调用模型、更新关系或写入记忆。
- 会话删除、角色切换、回复处理和控制回复共用会话 fencing 门闩；删除等待已领取任务结束，失效事件不会执行系统指令、关系/记忆写入或发送。
- 关停超时会显式取消后台、OneBot、插件和控制服务任务，并在有限窗口内关闭数据库连接池，未完成持久任务留待下次启动恢复。
- LLM 备用链的 `budget_tokens` 已按整条链共享的输出 token 上限执行；每次尝试先保守预留额度，网络失败且没有用量数据时不回收，避免备用模型重新获得完整预算。
- 控制协议会区分 JSON 语法错误、请求结构错误和未知操作；黑名单时长、列表参数及用户删除等边界输入均返回稳定业务错误，不因极端数值触发进程崩溃。插件异常退出、连接断开和握手超时会通知关停等待者，避免无意义地等待完整超时。
- 向量记忆接口仍保留为可选能力，但当前对话上下文不调用它；检索接口已强制带会话/用户范围并执行共享策略过滤；世界书暂不纳入本轮验收。
- 空壳调度器、只写日志的 EventProcessor 和审计 harness 已移除；Outbox、主动行为和插件各自保留真实调用链。

## 尚未证明

- 真实 QQ/NapCat 消息收发、真实外部 LLM 和长时间运行未执行。
- 插件 Unix socket 测试在普通测试命令中按 `#[ignore]` 标记；本机显式运行 15 个测试全部通过，CI 仍需单独执行 ignored 测试才能纳入必过门槛。
- `unknown` 发送结果仍是待核查终态；现在会保存生成内容和错误原因。`reply unknown check` 仅在任务有平台消息 ID 时调用 `get_msg`，平台明确返回“未找到”才自动重新排队；没有平台消息 ID 或查询网络失败时明确要求人工核查，不能把不确定结果当作未发送。
- 普通入站消息现在会按来源消息幂等地产生候选记忆，候选不会进入正常上下文或默认 ctl 列表；自然语言编辑请求的后台消费和矛盾修订尚未完成。自然语言编辑的 pending/failed/rejected/applied 状态会留在记忆元数据中，进程崩溃后可被发现，但尚无独立后台恢复队列。跨会话隐私禁用请求、确认和取消已通过 `memory sharing` 控制命令落库并在检索层生效。
- 控制回复已经复用回复任务和 Outbox；OneBot 超时缺少平台消息 ID 时仍无法自动查询，只能保留 unknown 状态等待人工核查。角色切换、停用或绑定版本变化会在发送前取消旧控制回复。
- 角色状态缓存与控制命令写入后的长期一致性、真实配置热重载和进程级关停仍需演练。当前 `reload-config` 对 LLM/decision 装配仍提示重启，不能声称模型路由已经热替换。
- 主动发言的静默时段仍按 UTC 解释，显式时区配置尚未接入；跨时区部署前不能把当前静默行为视为最终生产语义。
- 单 Provider 模式仍是首次发布的最小可用模式：一个兼容接口、一个凭据和一个默认模型覆盖对话与认知任务。多 Provider 路由已支持同一 Provider 复用多个模型、按任务配置备用链，并只在网络错误、超时、429 或 5xx 时切换；`decision.toml` 单独配置决策模型。Grok 按 OpenAI-compatible Provider 接入，真实 endpoint、模型名、额度和延迟仍待填写后验证。
- 语音能力尚未接入；当前 OneBot 出站只有文本动作，后续应以独立 VoiceGateway 接入，并把最终转写作为带来源 metadata 的消息写回现有记忆链。
- 用户换号的人工合并与删除已通过 `user merge` / `user delete` 控制命令接入，危险操作需要 `--confirm`；合并会迁移参与者和记忆、聚合关系及交互幂等记录，再删除来源身份。删除用户会在单一事务中删除普通与向量记忆、清除关系和旧 QQ 号/昵称，匿名化私聊路由并关闭该私聊主动发言、移除对应用户黑名单；历史消息正文、行和引用关系保留。SQLite 测试覆盖删除成功、其他用户数据保留、外键完整及失败回滚。

## 决策模型选型

当前源码只实现可替换的决策模型接口、超时和程序回退，没有把 Laya、Jev 或其他具体模型写死为生产默认。后续可以按场景配置本地或远程开源模型：参与判断优先低成本路径，关系和状态跨阶段变化使用更严格的复核路径；模型输出只能作为建议，最终由程序硬规则裁决。具体模型、部署位置、延迟和价格需要在真实摘要上单独测量后再写入配置与验收结论。
