## 当前实现

- 入站消息保存作者类型、平台用户身份、观察角色、提及、引用、绑定版本和来源 metadata；适配器只负责接受，插件事件由事务提交后的 `MessageAccepted` 唯一发布，并在插件协议中归一为一条 `message.received` 通知。
- OneBot 连接在下游入站队列积压时继续读取 WebSocket 并独立完成 Action 回执；最多暂存 1024 条入站事件，达到上限后会施加读取背压，极端积压下的回执时延尚未通过压力测试。
- 入站处理对数据库锁、连接和仓储暂时错误最多重试 3 次，重试期间保持消息顺序；解析错误、未绑定、黑名单命中和其他业务性拒绝不会重试。进程崩溃前仍留在内存中的事件无法恢复，尚未接入入站事件持久化队列。
- 消息接收入库使用结构化 `AcceptedMessageInput`，在同一事务中分配会话序号、写入消息并创建 Outbox 事件。
- 回复任务会按当前会话序号读取连续输入；原消息逐条保存，生成期间的新消息进入下一轮。当前批次冻结后会持久化最小 `reply_batches` 快照，只保留消息 ID、序号、事件 UUID 和上下文摘要，不保存完整 prompt。
- P3-2 已实现积压压缩：事件年龄超过批量等待时，冻结窗口扩展到当前时间并跳过批量等待；事件年龄超过回复延迟上限时跳过 `decision.delay_ms`。未积压事件仍保留原批量等待和决策延迟；过期阈值仍为 120 秒，被合并消息仍记录为 `batch_merge`。
- 上下文中只有角色真实发送且归属当前观察角色的消息才使用 `assistant`；当前批次只作为当前输入出现一次。
- 上下文历史中的系统用户标签使用会话内稳定匿名别名，不因身份标签向模型发送真实 QQ 号；昵称会移除控制字符、替换标签分隔符并限制为 32 个字符，正文、引用文本和当前轮中行首的伪身份标签会被中和。用户主动输入的正文仍按原文处理，关系、记忆和权限逻辑仍使用程序侧的全域用户身份。
- ctl 客户端、服务端和帮助文本使用统一 canonical 命令定义，支持一段、二段和三段命令；Unix socket 使用版本化结构化 `ControlEnvelope`，bot 不再解析人类 `cmd` 字符串。
- QQ 管理指令会先保存为 `author_kind=system_command` 的消息并创建 `MessageAccepted` Outbox 事件；Outbox 消费时由 `CommandHandler` 做权限和绑定校验，控制回复复用 `reply_tasks` 的生成、发送、未知和历史落库状态机，不再由适配器直接发送。
- 记忆候选与正式可见记忆分离；上下文只在来源会话读取会话记忆，跨会话仅读取当前全域用户且明确标记共享的记忆。跨会话记忆只作为角色的内部上下文使用，不向用户透露来源会话；没有用户身份上下文的接口只返回本会话内容。
- `memory update` 先把 pending 请求写入记忆元数据，再通过 decision LLM 生成受限修改建议；程序校验并做乐观并发检查后才写入，记忆原文不在普通控制响应中返回，模型不可执行删除动作。
- 自然语言记忆修改请求会由后台维护任务限量扫描并恢复；模型失败保留 pending 并记录重试信息，非法建议或超长结果标记 rejected，成功修改使用乐观并发检查后标记 applied。
- 跨会话记忆默认允许角色内部使用，但不把来源会话、原始群聊或记忆标识暴露给用户。用户可通过 `memory sharing request <character-id> <user-id>` 登记高优先级禁用请求；管理员使用 `memory sharing confirm ... --confirm` 后，未来跨会话检索会被数据库层阻止，来源会话仍可读取；`memory sharing cancel ... --confirm` 可恢复共享。
- 未配置对话模型时保留消息，不发送伪造回复。
- 黑名单在解析会话和参与者之前执行；查询失败按拒绝处理，不为被拦截目标创建新身份记录。
- 图片、文件等非文本段保存类型和平台字段，并以“没有媒体识别能力”的占位摘要进入上下文，不伪装成已完成识别。
- 关系交互按来源消息幂等记录，Outbox 重试不会重复增加熟悉度。
- 全域用户身份已落地：`users` 以 `(platform, external_id)` 唯一，用户参与者通过 `participants.user_id` 关联；关系数据库主键和领域对象均使用 `(character_id, user_id)`，会话 `participant_id` 只作为解析入口。同一平台用户跨群/私聊共享关系。旧关系迁移会按既定规则合并并有 SQLite 回归测试覆盖。
- 用户参与者写入时由仓储和 SQLite 触发器共同补齐全域身份；删除后的历史占位改为 `system` 角色，因此正常 `user` 参与者不会留下空 `user_id`。
- 用户合并会按显式来源和目标身份读取平台账号，不依赖数据库 ID 排序；状态控制中会话状态与心情写入使用同一 SQLite 事务，任一部分失败都会整体回滚。
- 关系交互幂等表也已从 `participant_id` 迁移为 `user_id`；旧数据按参与者映射到全域用户，重复的同一来源消息只保留一条，避免跨会话重复累计熟悉度。
- OneBot 当前把平台命名空间写为 `onebot_qq`，外部 QQ 号只作为该命名空间内的 ID；相同外部 ID 在不同平台会生成不同全域用户。关系服务的入口仍以会话 `participant_id` 定位，再由仓储映射到 `user_id`，这是内部适配边界，不是第二套用户身份。
- 单会话积压压测已证实当前串行回复链路会产生过期任务：以每秒 2 条、持续 60 秒、Provider 延迟 3 秒发送 120 条群消息，最终 27 条 Sent、64 条 Ignored、29 条 Expired；Sent 任务入库到发送延迟 P50 为 63,323 ms、P95 为 116,303 ms。该数据只说明隔离假 Provider/OneBot 下的当前行为，不代表真实 QQ 或多会话部署验收；第二阶段改动需维护者同意后再进行。
- `MentionOnly` 绑定下未被 @ 的消息现在会在记忆抽取、关系更新、批量等待和决策模型前直接标记为 `Ignored`；被 @ 消息仍沿原回复链路处理。该提前短路已由回复处理器单元测试覆盖。原压测绑定为 `Natural`，因此同一负载前后数据基本不变：改动前 `Sent=27、Ignored=64、Expired=29、P50=63,323 ms、P95=116,303 ms`，改动后 `Sent=27、Ignored=64、Expired=29、P50=63,323 ms、P95=116,301 ms`；该结果说明此次优化不影响 Natural 模式，但不能作为 MentionOnly 负载的收益测量。
- 记忆表增加可空 `user_id`；写入链路显式传入全域身份，不再通过 metadata 中的 participant ID 隐式回查。上下文与记忆仓储的跨会话查询明确接收 `user_id`；无用户身份时只读取当前会话记忆。
- 默认配置目录统一为启动目录下的 `config/`；首次启动逐份生成带占位说明的模板。根目录已有的本地配置不删除，继续使用时需显式传入 `--config-dir .`。
- 主动发言的每日额度已写入 `behavior_states`，进程重启不会清空当日计数；默认冷却为 10 分钟、每日最多 10 次。
- 普通回复支持绑定级可选限额：每用户每分钟、每会话每小时两个滑动窗口；默认关闭，被 @ 消息默认不豁免但使用 4 倍更宽限额。额度预留在行为引擎进入决策/生成模型前执行，命中返回 `rate_limited` 并把回复任务标记为 `ignored`；SQLite 事件表保留窗口数据，重启不会清空最近计数。
- 主动额度预留在 SQLite 事务中原子完成；并发后台 tick 只能有一个任务通过同一会话的冷却和每日上限检查，避免重复主动发言。
- 候选记忆保留来源和理由；后台使用 `llm_role=decision` 提出审核意见，程序只在来源消息、全域用户、会话、记忆类型和置信度门槛全部满足时正式化。模型不可用、输出不合规或意见为 `defer` 时候选继续保留；审核模型版本、理由和时间写入内部 metadata。
- 记忆候选抽取必须命中明确触发词；通用闲聊、疑问句和明显否定转折不会进入审核队列。候选正文最多保留 200 个字符，超长时在 metadata 记录 `truncated=true`；每个全域用户每天最多生成 20 条候选，超限只记录日志并跳过，不影响回复链路。该口径已于 2026-10-20 由维护者确认。候选审核由 `decision` LLM 自动完成，程序只执行来源、作用域和置信度硬校验，不要求维护者逐条确认。
- 插件只能读取当前会话可见的正式记忆；插件发送消息、修改角色状态、写入记忆和写入关系已在统一 RPC 分发层拒绝。角色、绑定和关系读取也必须带明确范围，关系读取使用全域 `user_id`，不能把 `participant_id` 当作稳定身份。
- OneBot 发送回执只有同时满足 `status=ok` 与 `retcode=0` 才视为成功，失败回执不会误标为已发送；未知结果核查到平台明确失败时会自动重新排队，网络核查失败仍保持人工核查状态。人工 `reply unknown retry` 也必须先查询平台，不能用确认参数绕过核查。
- 回复任务的生成领取、生成结果、失败回退、过期/取消/忽略状态和发送结果均受当前 Outbox 租约保护；失去租约的旧 worker 不会覆盖新 worker，过期的 `generating` 任务可由新租约接管。SQLite 竞态测试覆盖旧租约拒绝写入、新租约接管和发送状态保护。
- Provider 返回明确的 4xx、协议或配置错误时，Outbox 不再重复重试；回复任务进入 `failed` 终态并保留脱敏后的服务端错误说明。LLM 网络和 5xx 仍按 LLM 专用可恢复策略处理；429 会读取 `Retry-After`，空 choices、缺少 `message.content` 或响应 JSON 解析失败会按同一策略重试，退避不会超过事件 120 秒存活窗口。
- OneBot 明确返回失败回执时，发送任务进入永久失败并停止重复发送；连接未建立或出站通道暂不可用时保留生成内容并按可恢复错误重试。
- 平台自身回声只会写入已有会话的对账记录，不会因为回声创建新的用户或参与者；引用目标晚到时会在目标消息入库后回填本地引用关系，历史查询对同序消息使用消息 ID 做稳定排序。
- 会话删除会先把对应的待处理/处理中 Outbox 事件标记为死信；处理器入口再次确认源消息仍存在，避免删除后的事件继续调用模型、更新关系或写入记忆。
- 会话删除、角色切换、回复处理和控制回复共用会话 fencing 门闩；删除等待已领取任务结束，失效事件不会执行系统指令、关系/记忆写入或发送。
- 关停时先停止适配器、后台任务和插件，向控制请求报告结果并等待控制服务连接退出，最后关闭数据库连接池；超时会取消剩余工作，未完成持久任务留待下次启动恢复。控制请求仍可能在受限等待结束后被取消。
- OneBot 适配器关停只观察任务完成状态，不提前消费 `JoinHandle`；整体关停超时后的强制取消不会再次 await 已完成句柄，避免 Tokio panic。
- 角色 ID 重分配的事务回滚由集成测试中的 SQLite 触发器注入故障；生产服务不再读取全局 `YOMUA_TEST_FAIL_AFTER` 环境变量，避免并行测试设置环境变量时影响其他重分配操作。
- LLM 备用链的 `budget_tokens` 已按整条链共享的输出 token 上限执行；每次尝试先保守预留额度，网络失败且没有用量数据时不回收，避免备用模型重新获得完整预算。
- LLM 调度器的上下文和输出能力现在只按 `max_attempts` 范围内的模型计算；未启用的备用模型不会无谓压缩对话上下文。
- 控制协议会区分 JSON 语法错误、请求结构错误和未知操作；黑名单时长、列表参数及用户删除等边界输入均返回稳定业务错误，不因极端数值触发进程崩溃。插件异常退出、连接断开和握手超时会通知关停等待者，避免无意义地等待完整超时。
- 控制服务的 help 响应现在包含来自统一 schema 的 canonical 命令别名；ctl 的人类帮助和服务端结构化帮助使用同一份入口数据。
- 向量记忆接口仍保留为可选能力，但当前对话上下文不调用它；Provider 的 `embedding_model` 可从 `llm.toml` 的 Provider 注册表传到认知后台，未配置时跳过向量生成；检索接口已强制带会话/用户范围并执行共享策略过滤；世界书暂不纳入本轮验收。
- 空壳调度器、只写日志的 EventProcessor 和审计 harness 已移除；Outbox、主动行为和插件各自保留真实调用链。
- 配置结构中的 API key 与 OneBot access token 已自定义 `Debug` 脱敏为 `<redacted>`，不影响配置序列化、反序列化和相等比较；控制及插件 Unix socket 的父目录绑定前收紧为 `0700`，socket 文件保持 `0600`。
- 插件注册表、插件监督器和 OneBot pending 请求的标准互斥锁在中毒后会记录错误并恢复内部数据；pending 请求在确认后异常消失时返回失败而不触发 panic。

## 尚未证明

- MiniMax `M2-her` 返回 400（2013）的触发条件仍未查明，需要真实模型 endpoint 才能继续排查；此前最小请求成功、应用历史重放失败的现象尚不能确定根因。
- 入站事件仍无持久化队列；进程崩溃前只留在内存中的事件无法恢复。设计见 `docs/research/onebot-inbound-event-durability-design-2026-10-21.md`，本轮未实施。
- 限额开启后，每次限额检查引起的 SQLite 写入成本尚未测量。
- P3-2 两个提交后的同一手动压测均使用每秒 2 条、持续 60 秒、Provider 延迟 3 秒、120 条消息、隔离 SQLite 和假 OneBot/Provider。第 1 项（批量窗口扩展）实测：`p2_1` 为 `Sent=11、Ignored=109、Expired=0、P50=10,176 ms、P95=10,416 ms`；`p3_1` 为 `Sent=9、Ignored=111、Expired=0、P50=11,557 ms、P95=11,715 ms`，阶段批量等待 P50/P95 为 `1,509/1,510 ms`、决策延迟为 `1,403/1,403 ms`。第 2 项（积压时跳过批量等待和决策延迟）实测：`p2_1` 为 `Sent=21、Ignored=99、Expired=0、P50=5,942 ms、P95=6,022 ms`；`p3_1` 为 `Sent=16、Ignored=104、Expired=0、P50=6,528 ms、P95=10,606 ms`，阶段批量等待 P50/P95 为 `2/1,505 ms`、决策延迟为 `0/0 ms`。两条压测的 Expired 均为 0，P95 均较第 1 项下降；未引入丢弃策略，继续保留消息语义。

- 单会话积压压测 `p2_1_single_conversation_backlog_measurement` 与生产装配一致（SQLite WAL、5 秒 `busy_timeout`、5 个连接），但耗时约 1–3 分钟且曾出现并发写入锁竞争，因此标记为 ignored，不作为常规全目标测试的必过项。需要手动测量时运行：`cargo test --locked --test alpha_e2e_test p2_1_single_conversation_backlog_measurement -- --ignored --nocapture --test-threads=1`；GitHub Actions 通过 `workflow_dispatch` 触发同一命令。

- `unknown` 发送结果仍是待核查终态；现在会保存生成内容和错误原因。机器人自身回声在同一会话内正文完全一致、发送开始后 60 秒内且候选唯一时，会自动调用确认路径写入平台消息 ID 并收敛为 `sent`；内容不同、候选重复、跨会话或超出窗口时保持 `unknown`。该匹配只确认已有回声，不触发自动补发。`reply unknown check` 仍仅在任务有平台消息 ID 时调用 `get_msg`，平台明确返回“未找到”才自动重新排队；没有回声、没有平台消息 ID 或查询网络失败时仍需人工核查。

- 配置重载仅热更新当前已接通的运行时设置和日志过滤器；`shutdown_timeout_secs`、OneBot 连接、插件路径及模型路由变化要求重启。控制请求连接退出前数据库保持打开，避免并发请求访问已关闭的存储。

## 决策模型选型

决策模型已支持 Jev 的 TypeSafe System One 协议：程序把一次行为摘要作为 `state`，把动作选择作为 `choice` 问题发送，收到结构化答案后再经过现有验证器和硬约束。普通聊天模型仍可使用 OpenAI-compatible 协议。此前规划的“分级会议、权重、超时和预算配置”已废弃；超时、预算和备用链继续由统一调度器负责，复杂判断通过多个窄问题和代码组合完成。真实 Jev endpoint、额度和延迟仍需在隔离配置下验收。
