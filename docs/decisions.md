# 产品决定日志

本文件记录已确认的产品口径，作为实现和验收的唯一事实源。

## 2026-10-17

- 跨会话记忆仅供角色内部上下文使用，不向用户界面或回复直接暴露来源会话、原始内容或内部标识。影响：记忆检索、上下文组装、控制接口和验收文档。
- 连续消息保留每条原消息，但合并为一轮回复；合并时只能把尚未开始处理的回复任务标记为忽略，不能覆盖已生成、发送中或终态任务。影响：回复任务、消息仓储和并发测试。

## 2026-10-18

- 全域用户身份必须在应用调用链中显式传递：participant 只表示会话内作者，`user_id` 才用于跨会话关系与共享记忆；无用户身份时只能读取当前会话记忆。影响：OneBot 入站、上下文、记忆服务、认知后台、关系和 SQLite 仓储。
- 记忆候选不再由程序自评置信度后直接转正式；后台通过 `decision` 模型提出审核意见，程序按来源消息、用户、会话、记忆类型和置信度硬门槛应用，意见、模型版本和理由写入内部 metadata。影响：记忆服务、记忆维护、SQLite 记忆仓储和候选验收。
- Outbox 回复任务的生成领取和所有状态写入必须与当前租约原子绑定；旧 worker 失去租约后不得覆盖新 worker，过期的 `generating` 任务允许由新租约接管。影响：回复处理器、消息仓储、Outbox 竞态测试。
- 向量记忆是可选增强：Provider 可在 `llm.toml` 中配置 `embedding_model`，未配置时跳过向量生成而不影响文本对话；配置必须沿解析、装配和实际 Provider 调用链传递。影响：LLM 配置、主程序装配、认知后台和配置验收。
- LLM 路由能力必须只依据本次请求实际可能尝试的模型计算；`max_attempts` 未启用的备用模型不能压缩上下文或把已知能力降为未知。影响：LLM 调度器、上下文预算和备用链测试。
- 控制协议的帮助响应也必须从同一份命令定义提供别名，ctl 不得在本地和服务端维护两套命令入口。影响：控制 schema、服务端 help、ctl 输出和控制集成测试。
- 会话未绑定角色时，决策模型不得把规则引擎的 `Ignore` 覆盖为 `Reply`；未绑定属于程序硬约束。影响：决策上下文、模型触发、决策覆盖校验和回归测试。来源：2026-10-18 决策模型适配调查会话。
- 主动候选也经过决策模型；主动情境仅接受 `Keep` 或 `SuggestIgnore`，延迟调整与回复建议均不生效。模型否决发生在额度预留和主动消息入队之前。影响：主动行为驱动、决策编排/验证、主动队列及相关测试。来源：2026-10-18 主动行为决策接入会话。
- Jev 接入采用 TypeSafe System One 的单次 `state + choice` 裁决；废弃此前未实现的“分级会议”路线。Jev 只返回动作选择和置信度，超时、预算和备用链继续由统一调度器处理。影响：LLM Provider、决策服务、配置和验收文档。来源：2026-10-18 Jev 适配调查会话。
- 主动行为的静默时段和每日额度按可配置 UTC 小时偏移解释，默认 `+8`（北京时间）；`reload-config` 后后续决策立即使用新偏移。影响：运行时配置、行为引擎、主动驱动、行为状态仓储和配置文档。来源：2026-10-18 主会话阶段讨论。
- 插件继续使用现有 Unix socket + MessagePack 传输；本阶段只稳定 API、协议 DTO、错误码和测试，不新增 TCP、TLS 或 WebSocket 传输方式。影响：插件协议、传输层、插件文档和部署约束。来源：2026-10-18 主会话阶段讨论。

## 2026-10-19

- Jev 决策不再保留旧的聊天 JSON 兼容层，直接采用 TypeSafe typed questions 作为唯一决策协议；同一 state 发送 action choice、hard_constraints noul 和普通回复的 delay_delta_ms score，结果保留问题答案、概率、聚合置信度和模型版本。影响：DecisionResult、决策解析、验证器、TypeSafe 请求装配、主动行为和决策文档。来源：2026-10-19 主会话确认。
- 模型出站代理只在 `runtime.toml` 配置一份，统一应用于 TypeSafe 和 OpenAI-compatible HTTP 客户端；OneBot/NapCat WebSocket 始终直连，代理变化需要重启生效。影响：运行时配置、模型客户端装配、OneBot 网络隔离测试和配置文档。来源：2026-10-19 代理接入会话。
- LLM 配置只使用 Provider、Model Instance 和 Role 三层结构；移除旧版单 Provider `provider + options` 解析，旧字段作为未知配置拒绝。影响：LLM 配置解析、首次启动模板、部署配置和配置文档。来源：2026-10-19 主会话确认。

## 2026-10-20

- 普通回复增加绑定级可选限额：每用户每分钟和每会话每小时均按滑动窗口统计；默认关闭，被 @ 默认不豁免但使用更宽倍率。命中后在决策模型和生成模型前忽略，并把计数持久化到 SQLite 以避免重启绕过窗口。影响：CharacterBinding、行为引擎、回复任务、绑定查询、SQLite 迁移和限额测试。来源：2026-10-20 任务 5。

- 第一轮 AI 伴侣运行时改进采用渐进迁移：先加入默认不含正文的 PromptPlan/PromptTrace、固定 PromptSlot 和明确目标记忆 revision 事务；情绪衰减、主动意图和回复批次延后。影响：上下文装配、记忆仓储、控制处理、SQLite 迁移和阶段性验收。
- 明确目标记忆的 `replace` 保留旧记录并标记 `superseded`，`append` 创建独立正式记忆，revision 通过 `source_request_id` 幂等；候选审核的拒绝状态为 `rejected`，普通召回排除 candidate/rejected/superseded。影响：记忆状态、审核、检索和恢复任务。
- 阶段 2B 先建立结构化 `memory_claims` 的来源校验和历史持久边界；claim 的 replace/append/reject 只能由程序验证后的 proposal 调用，模型自动提出 claim 暂不启用。影响：记忆领域模型、SQLite 仓储、迁移和验收测试。
- 阶段 3 先提供独立的多维情绪衰减纯函数和 Mood 兼容投影，不接入现有默认状态更新链；离线衰减以持久化 `updated_at` 为基准，重复 tick 幂等，时钟回拨保留原状态。影响：情绪领域模型和后续可选后台能力。
- 阶段 4 先持久化主动意图和最小回复批次快照，状态更新使用条件写入和批次 lease token；暂不改变主动决策、Outbox 或平台发送协议。影响：主动行为恢复、回复批次和 SQLite 仓储。
- LLM 明确 4xx 业务拒绝保持永久失败；空 choices、缺少 `message.content`、响应 JSON 解析失败和 429/5xx 等供应商暂态响应进入 LLM 专用重试。429 的 `Retry-After` 受 120 秒上限和事件过期时间约束，死信只记录结构化日志，不自动向用户发送错误消息。影响：OpenAI-compatible Provider、ReplyProcessor、OutboxDispatcher、Outbox 状态和验收测试。来源：2026-10-20 任务 2。
- 模型上下文中的系统身份标签不发送真实 QQ 号；历史消息在同一会话上下文窗口内使用稳定匿名别名，昵称净化上限为 32 个字符，正文和引用文本中的行首伪身份标签会被中和。用户主动输入的正文仍按原文处理，关系、记忆和权限仍使用程序侧的全域用户身份。影响：ContextAssembler、上下文安全测试、README 数据说明。来源：2026-10-20 任务 3。

## 2026-10-21

- LLM 可恢复失败默认最多处理 4 次，退避基数为 4 秒（实际重试等待为 8+16+32 秒），在事件 120 秒有效期内为典型生成耗时保留 30 秒余量；`Retry-After` 继续同时受最大值和事件剩余有效期限制。数据库类、发送类错误及 4xx 永久失败策略不变。影响：OutboxDispatcher、回复过期判断和重试测试。来源：2026-10-21 评审任务 P2-1。
- 身份类记忆触发词保持当前范围，暂不进一步放宽，留待后期优化；原因是放宽会增加候选噪声与审核模型调用。当前范围包括句首或标点后的“我叫X”“我是X”（X 至少两字并排除疑问、否定和“我是说”语境）、“我的职业是X”以及“我在…工作/上学/读”，不恢复裸子串匹配，候选上限保持不变。影响：MemoryService 规则与触发词测试。来源：2026-10-21 评审任务 P2-2 维护者决定。
- OneBot 超时且没有平台消息 ID 的 `unknown` 回复任务，可由机器人自身回声在同一会话内按正文完全一致、发送开始后 60 秒内且候选唯一的条件自动确认；匹配不确定时保持 `unknown`，回声确认不得触发自动补发，无回声仍需人工核查。影响：消息接受、SQLite 回复任务、OneBot 回声对账、架构与现状文档。来源：2026-10-21 任务 7。
- 记忆候选只有命中明确触发词的消息才会生成；通用闲聊、疑问句和明显否定转折不进入审核队列，候选正文限制为 200 个字符并记录截断标记，每个全域用户每天最多 20 条候选。候选审核由 `decision` LLM 自主完成，减少维护者逐条介入；程序仍保留来源、作用域和置信度硬校验。影响：记忆服务、记忆仓储、后台审核成本和记忆抽取测试。来源：2026-10-20 任务 4 维护者确认及补充口径。

## 2026-10-22

- 消息积压时进行积压压缩：事件年龄超过批量等待后，冻结窗口扩展到当前时间并跳过批量等待；事件年龄超过回复延迟上限后跳过 `decision.delay_ms`。未积压行为保持原批量等待和决策延迟；过期阈值保持 120 秒，不丢弃消息，被合并消息仍记录为 `batch_merge`，生成期间到达的新消息进入下一轮。影响：ReplyProcessor、行为引擎延迟、积压压测和验收文档。来源：2026-10-22 评审任务 P3-2。
- CLI 专用依赖 `rustyline`、`crossterm`、`sysinfo` 保持为单包的必须依赖，不拆分 workspace，也不增加 feature 门控；理由是保持单一入口与简单构建，也方便其他贡献者改造控制器。背景比较：拆成 workspace 的 bot 与 ctl 两个 package，可让 `cargo run --bin yomua-bot` 和 bot 的 `cargo install` 不编译 CLI 依赖，但仓库内命令需明确 `-p`，CI 需分别构建/测试两个 package，文档中的 ctl 安装与运行命令也需更新；在单 package 中用 feature 门控改动较小，但若 feature 默认开启，主程序仍会编译 CLI 依赖，若默认关闭，则 `cargo run --bin yomua-bot-ctl` 和安装 ctl 需显式传 `--features cli`，CI 与文档同样需区分。影响：Cargo workspace、CI、部署与开发文档。来源：2026-10-21 评审任务 P4-2 维护者决定。

## 2026-10-24

- OneBot 入站持久化采用有界 SQLite inbox 与单一有序消费者；`runtime.inbound_durability` 第一版默认 `false`，待真实 QQ 环境验证后再以独立提交决定是否开启。容量上限为 1024 条待处理事件，终态保留 7 天后限量清理，每条事件最多处理 3 次后进入 `dead`；Action 回执仍按 `echo` 直接路由。影响：OneBot 连接、SQLite 仓储、消息接受事务、启动关停及部署配置。来源：2026-10-24 P5-1 实施要求。
- Inbox 只能恢复已提交的事件；帧读取后、inbox 事务提交前崩溃仍可能丢失，QQ/OneBot 重放能力未验证。持久输入不保证回复送达；旧版本遗留的内存事件无法迁移。影响：OneBot 入站可靠性说明与运维预期。来源：2026-10-24 P5-1 设计约束。
